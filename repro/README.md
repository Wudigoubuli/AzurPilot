# 空补给箱的数量被 OCR 读成 70 —— 最小复现（AzurPilot PR #1122）

这一组文件是为了让「行动力虚增 7000」这个 bug 能被**离线**复现：不需要游戏账号、不需要把补给箱用光，只要仓库本身 + 下面这几张裁剪图。

## 文件

- `box_big_untrimmed.png` —— 关键证据：第 3 个（100 点）补给箱数量槽，**36×22，原始未裁剪**
- `box_big_trimmed.png` —— 同一槽位、裁掉边缘残影之后
- `box_small_untrimmed.png` / `box_mid_untrimmed.png` / `oil_untrimmed.png` —— 另外三个槽位，用作对照
- `panel_context.png` —— 这些槽位在原生 1280×720 截图里的位置（大世界行动力面板）
- `repro-item-amount-residue.py` —— 最小脚本

来源：原生 1280×720 的实机截图，`module/os_handler` 的行动力面板，四个槽位（石油 + 20/50/100 三个补给箱）。

## 怎么跑

把文件放进仓库根目录，在仓库根目录执行（需要 OCR 服务可用，脚本会自己连 127.0.0.1:22268）：

```
python repro-item-amount-residue.py box_big_untrimmed.png
```

## 实测输出

| 槽位 | 绝对区域 | 未裁剪直接送模型 | 裁剪后送模型 |
| --- | --- | --- | --- |
| 石油 | (366,365,434,387) | `'852'` | `'852'` |
| 补给箱 1 | (571,365,607,387) | `'0'` | `''` |
| 补给箱 2 | (744,365,780,387) | `'0'` | `'0'` |
| **补给箱 3** | (917,365,953,387) | **`'70'`** | `''` |

箱子是空的（真实值 0），但把**未裁剪**的整块区域送进模型后，左侧那条图标残影连同 `0` 被读成 **70**：

```
box_sum = 0 + 20*0 + 50*0 + 100*70 = 7000
面板上的总行动力 25  →  算成 7025
```

然后脚本会一直去点「使用」、弹「道具不足」、点爆按钮、重启游戏 —— 也就是 issue 里那串现象。

## 说明

脚本只做三件事：读图 → `AmountOcr.pre_process()` → `atomic_ocr_for_single_lines()`，和 PR 里改动的重试逻辑**无关**，可以直接对着 `master` 跑；里面没有任何 stub，用的是仓库自带的 CnOCR 模型。
